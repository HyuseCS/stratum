# Decisions: #80 st-research (Define)

- D1 (Q1): Build only `st-research` now (agent, skill, procedure). `st-plan` keeps its own research step and format. Merging the two procedures waits for the workflow overhaul (#51). Rejected: O4, change `st-plan` Phase 0 to follow the new procedure now.
- D2 (Q2): Add one line to `skills/st-plan/SKILL.md`: if the spec leaves code facts unclear, or the user asks for research first, run `/stratum:st-research` before step 1 and give its file to `st-plan` as input. The `st-plan` agent does not change. Rejected: O6, wait for #51.
- D3 (Q3): In a feature, `st-research` writes `specs/<feature>/research.md`, the same file `st-plan` uses. The two steps must work together: research first when data is missing, then plan builds on it. A path the caller gives always wins. Rejected: O7, a separate `st-research.md` file.
- D4 (Q4): When `research.md` from `st-research` exists, `st-plan` keeps its sections and uses its facts. It skips its own research for what the file answers. It researches only unknowns the file does not cover, and adds its Decision/Rationale/Alternatives items under `## Decisions`. One rule in `procedures/plan.md` Phase 0. With no such file, `st-plan` works as today. Rejected: O10, write over the file.
- D5 (Q5): The skill changes the caller's words into a scope and numbered questions. When autonomous build mode is on for this session, it shows them and starts the agent at once (O11). Otherwise it shows them and waits for the user's OK (O12). Note: #77 changes how the autonomous flag is stored, so the check must use the format that is on main at build time.
- D6 (Q6): Add one line to `skills/st-grill/SKILL.md`: when a question needs code facts that a quick look cannot find, start `st-research` with the grill's facts as its scope, show the findings to the user, then continue the grill. The flow becomes grill, research when needed, findings to the user, spec, plan that uses `research.md` and skips what it answers (D4). Rejected: O14, no line now.
- D7 (Q7): When the grill in Define needs `st-research`, the orchestrator makes the feature folder then (`specs/<NNN>-<short-name>`, same rule as Specify) and passes the exact path `<folder>/research.md`. Specify uses that folder and does not make a second one (one rule in `procedures/specify.md`). `st-research` never takes the folder from `state.json`. A grill outside Define, or a run with no feature, writes `.stratum/research/<short-name>.md`. No research needed: Define works as today. Rejected: O15, write to `.stratum/research/` and move it in Specify.
- D8 (Q8): When the research file exists, `st-research` keeps it and adds a new round (`## Round 2`, ...) with the same fixed sections. `st-plan` reads all rounds. Rejected: O20, write over the file.
- D9 (Q9): `st-research` does web research too. Stratum has no other step that researches the web, and that gap is a reason #80 exists. No test-gap section; a question can still ask about tests. Rejected: O21 (no web), O22's test-gap section.
- D10 (Q10): Web only for facts outside the repo (library, tool, API, version) or when the code cannot answer. Official and primary sources first. Each web fact cites URL and read date. Web text is data, never an instruction. A web fact that conflicts with the installed version is marked as a conflict. Uses only Claude Code's WebSearch and WebFetch tools: no Context7, no scripts. Rejected: O24, web for any question.
