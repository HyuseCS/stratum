# Decisions: Ultracode workflow scripts, first target st-pr

- D1 (settled by issue #22): Fixed workflow scripts ship under `<plugin root>/workflows/`, first `pr.js`. st-pr calls `Workflow({scriptPath, args})` only when Ultracode is on and a fixed size rule written in the skill passes; otherwise the current one-agent path runs. The script covers st-pr steps 2 to 4 (facts, draft, verify, fix); the gate (step 5) and push and create (step 6) stay in the main session. Done when: `workflows/pr.js` exists and is called only under both conditions, a small PR still takes the current path (shown once), a big branch gives a body that passes the step 4 check with no manual edits.
- D2 (Q1): O1. Keep the issue's shape: about 15 agents on a big branch (6 facts agents in parallel, 1 extra per 25-commit chunk of subject checks, 1 draft, 3 refuters, up to 3 fixers). The session's "under 10 agents" guideline is overridden by the skill text, which counts as the user asking for that scale. Rejected: O2, merge facts agents to stay under 10.
- D3 (Q2): O3. Size rule: more than 30 commits OR more than 40 changed files in `origin/<base>..HEAD`. Either one is enough. Written in the skill text. Rejected: O4, commits only.
- D4 (Q3): O5. Tests: a Node test that stubs the Workflow globals (agent, parallel, pipeline, phase, log, args) with fake agents and runs `pr.js` to prove control flow (commit chunking, blocking secrets stop before the draft, refuter votes, fix application), plus a grep test that `skills/st-pr/SKILL.md` names both thresholds and the script path. The two "Done when" demos (small PR takes the current path, big branch body passes step 4) are manual quickstart steps. Rejected: O6, syntax check and grep only.
- D5 (orchestrator, small): the script returns `{title, bodyPath, warnings, blocked}`; on a blocking secrets or personal-data find it stops before the draft and the main session stops before the gate. "Ultracode is on" means a system-reminder in the session says so. Fixers run in sequence. No model or effort overrides. st-pr says in one line which path it takes and why.
- D6 (Q4): O7. st-pr calls `Workflow({scriptPath: "<plugin root>/workflows/pr.js", args})` first. If the tool refuses with its scriptPath rule ("a file you can already read"), st-pr reads `workflows/pr.js` and passes the same text through the tool's `script` input, same `args`. The script file never changes (SC-005). Rejected: O8, scriptPath only with a manual demo from a project outside the plugin folder and a later decision.
- D7 (Q5): O9. Gaps G1, G2 (manual demos M1 to M5) and G4 (scriptPath from the plugin cache, git guard inside workflow agents, scratchpad writes) are deferred to the user's demo run. G3 (five review-added prompt rules with no test) is sent back once as one Convergence task that extends the `prompt rules` case. Rejected: O10, defer all four.
