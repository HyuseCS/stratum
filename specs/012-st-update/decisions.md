# Decisions: st-update (#73)

- D1 (Q1): Check items, not whole files. Stratum keeps one list of harness items, each with a rule (a line in `.gitignore`, `statusLine` points at the current plugin, install version is current). st-update adds or fixes only that line or key, never rewrites a whole file, and never changes user data files. A key that holds a value Stratum did not write gets a diff and a question. Rejected: O2, a hash record written by st-init (no project has one, so it needs the O1 rules as a fallback anyway).
- D2 (Q2): st-update runs `claude plugin update stratum@stratum` itself in each folder that has an install record: the main checkout, each linked worktree that exists, and their subfolders with a record. It keeps each record's scope. A record whose folder is gone is listed, not touched. A failed run shows the error and the exact command for the user. Rejected: O4, print the commands only.
- D3 (Q3): st-update takes an optional folder argument (default: the current project), so it can run from any session that has the new Stratum for any project. The README gives the one manual first-time command (`claude plugin update stratum@stratum -s local`). Rejected: O6, no argument and a manual update plus restart first.
- D4 (Q4): st-update points `.claude/settings.local.json` `statusLine` at the install path of the updated record (`cache/stratum/stratum/<version>/statusline/st-statusline.sh`) in the same run as the plugin update, so statusline and plugin keep one version. The current install path is current. Any other Stratum statusline path (old cache version, missing path, the source folder) is outdated and gets repointed. A missing entry is new. A non-Stratum command gets a diff and a question (D1). Rejected: O7, the marketplace folder (never stale, but the statusline can run newer code than the plugin; the user found this).
- D5 (Q5): "Discontinued" means a harness feature that is no longer in the Stratum repo or the published version. The plugin update removes the feature itself. st-update finds its traces in the project with two checks. Names, automatic: each Stratum name in the project (agent keys in `.stratum/models.json`, `stratum` skills and tools in `permissions.allow`) that the current version does not have is discontinued. Files, a short list: starts with `.stratum/commit-mode`; a change that removes a feature which wrote a project file adds that file to the list. Rejected: O12, a hand list for names too (easy to forget per removed agent or skill).
- D6 (Q6): New items that need no question (a `.gitignore` line, a pointer line, `statusLine`) are added after the gate. For each missing file that st-init asks about (`git-guard.json`, `models.json`, `advisor.json`, `powerline.json`), st-update asks that st-init step's question after the gate, one at a time, each with a "skip" answer that leaves the file missing. It never writes a default without asking. Rejected: O14, list them and send the user to `/stratum:st-init`.
- D7 (Q7): st-update also updates the committed harness files (`.gitignore`, `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`) in each linked worktree, with one commit per worktree branch through the commit guard, exact paths only. Per-folder items (install, `statusLine`) are updated everywhere too. Rejected: O15, committed files in the target folder only.
- D8 (Q8): Before it changes a committed file in a worktree, st-update checks `git status` for that file. With uncommitted changes, it skips that file in that worktree and lists it in the report with the reason. The gate table has one row per worktree, and the user can say "skip <worktree>" at the gate. Rejected: O18, a diff and a question per dirty file.
- D9 (Q9): A test fails when st-init and the st-update item list differ (`.gitignore` lines, pointer lines, `.stratum/` files, settings keys), proven with a negative control. st-init stays as it is. Rejected: O20, a DESIGN.md rule only.
- D10 (Q10): A `.gitignore` line, the constitution pointer or an `enabledPlugins` false entry is current when its effect is in place from any source: `git check-ignore` ignores the path (`.git/info/exclude` counts), `AGENTS.md`, `CLAUDE.md` or `CLAUDE.local.md` names `.stratum/constitution.md`, or the key is false in `.claude/settings.json` or `.claude/settings.local.json`. A missing item goes in the place st-init uses. Rejected: O22, only st-init's exact line in st-init's exact file (would commit to 12 branches of a team repo with a personal install).
- D11 (Q11): When a project hook denies its commit, st-update quotes the hook's deny reason and gives the exact command (`git -C <checkout> add -- <paths> && git -C <checkout> commit -m "<message>"`). The published skill names no personal path; the spec edge case changes to match. Rejected: O24, name `~/.claude/veent-commit-ask.sh` in the skill.
