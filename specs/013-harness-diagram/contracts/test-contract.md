# Contract: `tests/test_harness_model.sh`

## Call

```bash
bash tests/test_harness_model.sh [check...]
```

- No argument: run every check, in the order of the table below.
- With arguments: run only the named checks. An unknown name prints `FAIL unknown check <name>`.
- `ST_ROOT=<folder>` makes the test read that folder in place of the repo (as
  `tests/test_local_files.sh` does), for negative controls in a copy.
- The pinned version is one variable, `v=1.60.0`. Every `npx` call is `npx -y "likec4@$v"`.
- The test never writes in the repo. Temp files go in `mktemp -d`, removed by `trap ... EXIT`.
  It needs no `[lock]`.
- Bash, with an inline `python3` parser for the block checks. No other tool.

## Output

One line per result, the same shape as the other tests in `tests/`:

```text
ok   <check>: <what passed>
FAIL <check>: <what failed, with the name or path>
SKIP <check>: <reason>
```

Exit 1 if any line is FAIL, else 0. SKIP does not fail.

## Checks

| Check | FR | Passes when | FAIL line names |
|-------|----|-------------|-----------------|
| `coverage` | FR-002, SC-001 | Each item below has an element. Runs as `coverage-skills`, `coverage-agents`, `coverage-hooks`, `coverage-statusline`, `coverage-scripts`, `coverage-procedures`, `coverage-data`, each also callable alone. | `missing` | FR-002, SC-001 | Every `path '...'` in `model/*.c4` exists under the root. Every `data '.stratum/...'` is still found by the `.stratum` grep. | the path |
| `summaries` | FR-003 | Every element block has one `summary` line, 1 to 200 characters, at most 2 sentences. A line `<name> = <kind> '...'` that does not end in `{` (an element with no block) is a FAIL. | the element id |
| `links` | FR-004, SC-003 | Every line with `->` in `model/*.c4` matches the relationship pattern in model-format.md, with a kind from the 5 and a non-empty label. | file and line number |

| `vendored` | FR-008 | Each element whose path is one of the 11 vendored skills (data-model.md) has `#vendored`. No other element has it. A vendored skill with no element is not this check's failure (that is `coverage`). | the element id |
| `views` | FR-005, FR-006 | In each `views/*.c4` that exists: every dynamic step line has a label `(n) ...`, numbered 1, 2, 3 ... in file order; Full has at least 3 gate steps, Fast at least 1, Design at least 1 (`(n) gate: ...`). The actors `user`, `codex`, `advisor`, `github` are declared in `model/0-spec.c4`. No backtick in any `.c4` file. | the view and step number |
| `page` | FR-009, SC-006 | `docs/harness/README.md` exists, its first line is `<!-- Generated by likec4 export markdown. Do not edit manually. -->`, its `### ` headings are exactly Full lane, Fast lane, Quick lane, Design lane, Agents, Harness, Data flow in that order, and it has 7 Mermaid blocks. | the missing or extra heading |
| `readme` | FR-010, FR-011 | The main `README.md` links `docs/harness/README.md`, names `npx -y likec4@<v> validate docs/harness`, `npx -y likec4@<v> export markdown docs/harness`, `bash tests/test_harness_model.sh`, `claude mcp add --scope user likec4 -- npx -y @likec4/mcp@<v>` and `22.22.3`, with `<v>` the test's variable. | the missing text |
| `nomcp` | FR-012 | No `.mcp.json` at the root. `.claude-plugin/plugin.json` does not contain `likec4`. `docs/harness/` holds only the files in model-format.md. | the file |
| `validate` | FR-013 | `npx -y likec4@<v> validate <root>/docs/harness` exits 0. | `likec4 validate failed` and the tool's error lines |
| `rebuild` | FR-009, FR-013, US4-3 | Copy `docs/harness/` to a temp folder, delete the copy's `README.md`, run `npx -y likec4@<v> export markdown <copy>`, and `diff` the new README with the committed one: no difference. | `page is not rebuilt` and the first diff lines |

`SKIP <check>: node <version> is below 22.22.3` when `node --version` is lower (D9). Any other
failure, for example no network on the first download, is FAIL with the tool's message, not SKIP.
