# Decisions: Codex advisor (issue #18)

- D1 (Q1): O3. Build the claudex-loop shape inside Stratum as one script `scripts/st-advisor.sh`. It runs `codex exec -s read-only --ephemeral --output-schema <schema> -o <file>`, checks exit code and JSON validity, prints findings with a verdict (APPROVED, REVISE, BLOCKED). Empty or failed reply is BLOCKED, never approval. SHA256 tie and verdict are spec requirements. Rejected: O4 reuse codex-plugin-cc (second plugin, no programmatic call, no verdict); O1 plain script with no verdict.
- D2 (Q2): O5 as default, with O6 as a user-selectable option. Codex is the advisor when `codex` is on PATH; `/advisor` is not consulted unless the user picks "both". Missing `codex`: one line `no advisor: codex not found`, exit 0, flow as today (`/advisor` if set). Codex present but failing: `BLOCKED: <reason>`, orchestrator shows the line and asks the user whether to continue. Never silent, never approval. Rejected: O6 as the only mode (double cost every time).
- D3 (Q3): O7. New file `.stratum/advisor.json` with `{"mode": "codex"}` (default when missing) or `{"mode": "both"}`. The script reads it and prints the mode so the orchestrator knows whether to also run `/advisor`. `st-init` asks one question and writes it. Rejected: O8 a key in `git-guard.json`.
- D4 (Q4): O9. The prompt names paths and a base SHA; Codex reads the rest itself in the read-only sandbox. Plan point: paths of spec.md, plan.md, tasks.md. Test point: task text, test path, both failure outputs pasted. Diff point: base SHA, Codex runs `git diff <base>`. Four skill files change: st-inspect (plan point), st-build (test and diff points), st-fast (test and diff points), plus README. Rejected: O10 paste full content.
- D5 (Q5): O11. One round per point, at most two. The script appends a record to `specs/<feature>/advisor.md`: point, SHA256 of the input (plan.md, the diff, or the test output), verdict, findings. APPROVED continues. REVISE: findings go through the normal finding path; if the plan or diff changes, run the script once more. BLOCKED stops and goes to the user. At the gate the orchestrator shows the verdict and checks the recorded SHA against the current input; a stale SHA is "advisor approval is stale", not approval. Rejected: O12 a 5-round loop.
- D6 (Q6): O13. No hard block. The prompt tells Codex to stay inside the named files and the diff and never open env or secret files. README states each call sends the prompt and the files Codex reads to OpenAI; `"mode": "off"` in `.stratum/advisor.json` is the off switch. Codex is review-only: always `-s read-only`, never a write sandbox, never `codex exec` for a fix or build; the script, the skill text and the README say so. The record and the test prove that the script never passes a write-capable sandbox flag. Rejected: O14 a scrubbed throwaway worktree.
- D7 (user): the advised session waits. The script runs in the foreground; the orchestrator blocks on the Bash call until Codex returns and the record is written, then reads the verdict before moving on. No background run, no polling. A timeout is `BLOCKED: timed out`, never approval. Foreground Bash caps at 10 minutes; Plan measures each point before any timeout is set.
- D8 (user, Plan phase): the Codex model is configurable. `.stratum/advisor.json` takes optional `model` and `effort` keys, passed to Codex on each call. Missing keys mean the user's own Codex config. `st-init` writes only `mode`; the user adds `model` or `effort` by hand. Replaces the earlier small decision "no override".
- D9 (orchestrator, Plan phase, from plan finding F2): the diff-point hash input excludes `specs/<feature>/advisor.md` (else every diff approval goes stale on its own record) and includes untracked files (the Fast lane has them at its diff point). FR-007 amended.
- D10 (Q7): O15. The plan-point hash covers `spec.md`, `plan.md` and `tasks.md` joined in that order, since Codex reads all three. Replaces the plan.md-only input of D5. Rejected: O16 plan.md alone.
- D11 (Q8, Inspect phase, from inspect finding F4): O18. A missing `.stratum/advisor.json` means `off`. The script prints `no advisor: mode not set. Write .stratum/advisor.json with "mode": "codex", "both" or "off".` and exits 0; the orchestrator shows the line. Nothing leaves the machine without a user decision. `st-init` writes the file for new projects. The README advisor bullet names it (the README has no "Breaking changes" section). Replaces the "missing file means codex" part of D3 and D2. Rejected: O17 keep the default with a one-time notice.
- D12 (Q9, Inspect phase, from inspect finding F3): O19. At the diff point, untracked paths matching `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx` are left out of the list sent to Codex but stay in the hash. The prompt gains the line "Never quote a secret value in a finding." Both have a test. Rejected: O20 prompt line only.
- D13 (orchestrator, Inspect phase): inspect F5 (env variables visible to Codex's shell: unknown) is accepted and stated in the README. Inspect F14 (hash contracts/ and data-model.md too) is dropped: D10 stands, the three files Codex is told to read are the hashed input.
- D14 (orchestrator, Inspect phase): inside `.stratum/advisor.json` the `mode` key is required. A file with only `model` or `effort` is `BLOCKED: bad advisor.json`. Follows D11: Stratum never assumes `codex`.
- D15 (orchestrator, Inspect phase, from inspect F2 second run): whether Codex loads a committed project `.codex/config.toml` is tested once at T011 with a logged-out run in a scratch repo (no quota). If it loads, the README says a committed `.codex/config.toml` can change the Codex model, provider or host, like any committed code. No code guard.
- D16 (orchestrator, Build phase, from the US2 review): the BLOCKED reason for a codex error is the last stderr line that starts `ERROR:`, else `codex exited <rc>`. The "last non-empty stderr line" fallback is dropped: Codex stderr carries the session text, and that line goes into the committed record. Research R2 and the script change; the test adds the `codex exited <rc>` case.
- D17 (orchestrator, Build phase, live run L1): Codex reviewed the plan and said REVISE with three findings. (1) "validator omits summary, severity enum, extra keys": dropped. The script rejects a missing or non-string summary; the schema Codex answers under enforces the enum and forbids extra keys; every field the script writes is cleaned text. (2) "files joined with no separator let a boundary move keep the hash": dropped. It needs an edit crafted to move exact bytes across a file boundary; a forged record is the accepted risk of plan S4, and any ordinary edit changes the bytes. (3) "probe cannot settle the trust-dependent risk": fixed before the run. T011 probed both trust states; the trusted state loads the project config, so the README sentence from D15 is in.
- D18 (orchestrator, Build phase): `specs/006-codex-advisor/advisor.md` is kept and committed; it is this feature's own record (one REVISE, one BLOCKED from the logged-out run, one user-continued). `.stratum/advisor.json` with `{"mode": "codex"}` stays uncommitted until the user decides whether this repo runs the advisor by default.
- D19 (Q10/Q11): the diff-point Codex review ran on 2026-10-23 (REVISE, two MEDIUM findings, both real and fixed: the three advisor.md commit lines are now conditional on a change, and the `[P]` escalation runs the advisor from the worktree root and sends st-debug there). `.stratum/advisor.json` with `{"mode": "codex"}` is committed, so this repo runs the advisor. Rejected: skip the diff point; remove the file.
- D20 (orchestrator, Build phase, diff point round 2): Codex found that a failed hash (no `sha256sum`, an unreadable input) left an empty or partial digest that `check` then matched, so a stale approval could pass. Verified by hand and by test (red before, green after). Fixed: inputs must be readable regular files, and a digest that is not 64 hex characters stops the run with `cannot hash inputs`, exit 2, before any record. No pipefail: `git diff --no-index` exits 1 by design. The two round-1 findings did not come back. The fix makes the round-2 record stale and both rounds of this gate pass are used.
- D21 (Q12, diff point round 3, user-approved extra round): Codex found that the diff hash ignored git exit codes, so an unreadable untracked file gave no diff bytes and left an earlier approval fresh. Verified by hand (git prints `fatal: cannot hash`, zero bytes) and by test. Fixed: `git ls-files` and the diff producers must succeed (`git diff --no-index` may exit 1), else `cannot hash inputs`, exit 2, no record. Three rounds ran on this gate pass; the record is stale again after this fix.
- D22 (user, PR #40 Codex review, 2026-10-23): three findings, each checked against the script and fixed test-first in its own commit. C1: the diff-point prompt now excludes `.env*`, `*.pem`, `*.key`, `*.p12` and `*.pfx` at any depth from the `git diff` Codex is told to run, while the local hash still covers them (a tracked secret edit stays a stale trigger). C2: `set -o pipefail` and a status check on each hash assignment, so a failing `cat` or `sha256sum` is `cannot hash inputs`, exit 2, not a plausible digest. C3: `APPROVED` with a non-empty findings list is `BLOCKED: APPROVED with findings`, the mirror of `REVISE with no findings`. The review file `PR-40-REVIEW.md` stays untracked and uncommitted; it is the user's note.
- D23 (orchestrator, PR #40 round 2 note, 2026-10-23): the Codex call gets `--ignore-user-config`. Reason: `~/.codex/config.toml` can start MCP servers, hooks and notify commands during a review-only call, and `-s read-only` does not cover those; the flag skips that file while auth still works (probed live with a one-word prompt in a scratch repo: exit 0, answer `ok`). Cost: the user's default model and the trusted-project list are not read, so a project `.codex/config.toml` does not load either (the D15 risk goes away) and the model falls back to Codex's own default (`gpt-6.1-sol` today). The model and effort therefore come only from `.stratum/advisor.json`; this repo sets `"model": "gpt-6-astra"` to keep the model it used before. Rejected: no flag (keeps the user's model by default, but every review runs whatever the machine's Codex config starts).
- D24 (orchestrator, PR #40 round 2): shrink items. F13 (one printf per test-point input) and F14 (untracked list built in a subshell) are applied; the prompts were byte-identical in every covered case. F15 and F16 (delete duplicate prompt-head checks; one exact argv check in place of two) are dropped: both delete test checks, and the permission guard denied that deletion in the build agent's session; they stay as the reviewer's proposal. F17 (inline the `gitc` test helper) is dropped: the helper has three callers since the C1 test.
- D25 (user, PR #40 round 2 F6): FR-013 is amended. The secret-name filter is case-insensitive and covers `.env*`, `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `.npmrc`, `.netrc`, `.pypirc` and `credentials*` in any directory, both in the untracked list given to Codex and, with `icase` pathspecs, in the `git diff` command Codex is told to run. The hash still covers every one of them. Supersedes the five-name list in D12 and D22.
- D26 (user, 2026-10-23, change `changes/001-codex-plan-only.md`, Q1 branch B): Codex reviews the plan only, now at the end of `st-plan` (step 4), before the Plan gate. `st-inspect` keeps only `check plan` at the build gate. The `st-build` test point stays on Codex (rare). The `st-build` diff point and every `st-fast` point go to `/advisor` (pre-#18 wording). The script loses the `diff` form (`diff`, `check diff`, `continued diff`), the untracked filter and the diff hash. FR-013's diff-point filter goes; its prompt rules stay. Supersedes the diff-point parts of D9, D12, D22 C1 and D25. Reason: diff reviews cost about 37,000 tokens each and ran up to three rounds per feature (D19 to D21). Rejected: keep Codex in `st-fast` or on the diff.
- D27 (user, 2026-10-23): Codex at the plan point only advises on a better build or another approach for a better outcome: a simpler approach, tasks to cut or merge. It does not check correctness, coverage or risks, because `st-inspect` does that, and the user does not want Codex tokens spent on that. The plan hash leaves out plan.md's `## Validate` section, so the approval from `st-plan` step 4 stays fresh after `st-inspect` writes that section. A real plan fix still makes it stale. Rejected: two Codex plan reviews per feature (about 74,000 tokens).
- D28 (user, PR #43 review F1): the `## Validate` cut in the plan hash skips fenced lines: a `## Validate` or `## ` line inside a code fence neither starts nor ends the cut (`/^```/{f=!f}` toggle in `st-advisor.sh`). Reason: a fenced `## Validate` in the plan body hid every line after it up to the next heading, so a real plan fix kept the same hash.
