# Decisions: #79 on-demand Codex review (Define)

- D11 (Q11): Add a new point `st-advisor.sh review <base> [<head>]`. No feature folder needed. It always runs Codex when Codex is installed; only mode `off` stops it. Same schema, prompt rules, tab and answer check as the other points. The `diff` point and the lanes do not change. Rejected: O26, a separate script.
- D12 (Q12): No pinned copy. The on-demand review runs only when the work is finished, so nothing changes during it. It runs in the folder that holds the finished code and reviews `<base>..HEAD` there; the point is `st-advisor.sh review <base>` (no `<head>` argument). The existing before/after snapshot makes it BLOCKED if anything changes. Rejected: O27, a temporary worktree pinned at `<head>`.
- D13 (Q13): The record goes to `<main checkout>/.stratum/advisor/<branch>.md` (`/` in the branch name becomes `-`; detached HEAD uses the short commit id). Each run adds an entry and keeps old ones. Add `.stratum/advisor/` to this repo's `.gitignore`; in other projects the file shows as untracked. Rejected: O30, the worktree's own `.stratum/advisor/`.
- D14 (Q14): The review uses the Codex tab first (no time limit). Headless runs only as a fallback: not in herdr, tab busy, or tab name in use elsewhere. The output says which one ran. Rejected: O33, tab only with no fallback.
- D15 (Q15): The headless fallback of `review` has a fixed 1800 s limit. Other points keep 540 s. Rejected: O32, a limit that grows with the diff size.
- D16 (Q16): `/stratum:st-advisor` takes nothing (merge-base with main..HEAD here), a base ref (`<base>..HEAD` here), or a PR number (find the local worktree with the PR branch checked out, check its HEAD is the PR head commit, review there; else stop and say why). It starts the watch and answers tab prompts like the lane points, and checks each finding against the source before showing it. Rejected: O36, base ref only.
- D17 (Q17): Codex does a full review: bugs, regressions, security, broken constitution rules. If the user names a plan or spec file (any path, any format), Codex also checks the diff does what it says. No file: no plan check. Rejected: O38, the narrow `diff` prompt.
- D18 (Q18): For the PR form only (`#N`), the skill also runs `coderabbit review --agent --committed --base-commit <base>` itself, at the same time as Codex. Its findings go in their own section of the same record file, and the orchestrator checks each one against the source before showing it. Works with the headless fallback; no network prompt in the tab. The user chose to send PR diffs to CodeRabbit. Rejected: O39, Codex runs CodeRabbit in its tab.
