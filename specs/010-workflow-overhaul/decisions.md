# Decisions: workflow overhaul (#51, #48, #55)

Findings from the grill:

- F4. #55 says Stratum prescribes the `pgrep -f vitest` wait loop. No Stratum file has `pgrep` or a wait loop; it came from the parasat constitution.
- F5. #48 says st-plan and `procedures/tasks.md` write a full-suite step. No Stratum file does; only `agents/st-quick.md:47` forbids the full suite.

Decisions:

- D1 (Q1): O3. Normal mode: the orchestrator never answers a worker's permission prompt; it tells the user the tab and the prompt. Autonomous build mode (the user turns it on): a Stratum permission hook in each worker sends the prompt to the orchestrator. The orchestrator approves small, safe prompts (a test, a lint, an edit in the worker's own worktree) one time only. Risky prompts go to the user in short, simple words (scr and eli) with the tab name. Never approved by the orchestrator: push, force-push, deleting a branch or worktree, `reset --hard`, anything outside the worker's worktree, secrets or `.env`, new dependencies, network calls to new hosts. Every approval is recorded and listed at the end of the run. When the classifier blocks an approval, Stratum tries no other way and the prompt goes to the user. Plan checks that the Claude Code permission hook supports this; if not, autonomous mode falls back to permissions the user grants at worker start. Big decisions (spec, scope, approach, planning) go to the user. Small decisions go to the advisors; any advisor can send one to the user. Rejected: O4, the orchestrator answers permission prompts with send-keys in every mode.
- D2 (Q2): O5. Subagents stay the default for `[P]` tasks. When the user says so ("build with workers", "US2 on the laptop"), Build sends a phase's `[P]` tasks to `st-worker`, and D1 applies to those workers. Rejected: O6, `st-worker` stays out of Build.
- D3 (Q3): O7. The planner splits the work so that as many tasks as possible get `[P]`. User stories that share no files also run at the same time. Each `[P]` task lists the files it owns, and no two tasks that run at the same time own the same file. Tests that cannot run at the same time are marked, and Build runs them one at a time. Rejected: O8, keep today's `[P]` rule.
- D4 (Q4): O9, with a mode choice. A new screen is a page or view the app does not have yet (not a new part of an existing page, not a dialog). The planner marks each new-screen task, and at the Plan phase the user picks its Design lane mode: autonomous (existing look), new look (the user's "manual design": grill, design file, gate), or custom design (#57, offered only after #57 is built). Build sends the task to `/stratum:st-design` in that mode and goes on with the other tasks while the screen waits. The user sees the screen's report with the story review. Changes to existing screens stay with `st-build` + `st-ui-ux`. Rejected: O10, new screens stay with `st-build` + `st-ui-ux`.
- D5 (Q5): O11. When the Design lane cannot start in Build (tool check fails, no dev server), Build pauses only that screen task, tells the user what is missing in short, simple words, and goes on with the other tasks. On the user's "go" it runs the screen again. It never changes to `st-ui-ux` without telling the user. Rejected: O12, change to `st-build` + `st-ui-ux` and note it in the report.
- D6 (Q6): O13, without the copy rules. Remove `st-frontend-design`: the skill folder, its license file, its `vendor.lock` entry, and its rows in `THIRD_PARTY_NOTICES.md`, `README.md` and `DESIGN.md`. It was never wired (D11's "design brief" step was never built), and the Design lane now owns that job: grill, hallmark themes, design file, hallmark lint, impeccable critique (which already reviews screen copy). `agents/st-build.md:44` reads the design file (`DESIGN.md`) in place of "the project's design brief". Rejected: O14, keep it as a manual tool; and adding its copy rules to `agents/st-design.md`.
- D7 (Q7): O15. When a task names GitHub issue numbers, `/stratum:st` runs `st-triage` on them first (one read-only agent per issue, side by side), shows a short verdict per issue, then picks the lane. Rejected: O16, `st-triage` stays manual only.
- D8 (user): Remove the "Make GitHub issues from the tasks?" question from the Plan phase gate (`skills/st-plan/SKILL.md`, `skills/st-full/SKILL.md`), and change the issue rule in `skills/st/SKILL.md` to match. Stratum never makes issues from plan tasks; it makes an issue only when the user asks in their own words. `/stratum:st-issues` stays as a manual tool.
- D9 (Q8): O17. `st-herdr-workspace` stays a manual tool. When the user asks the orchestrator to open workspaces for agents to work in by themselves, the orchestrator does so through `st-worker` (D10), in autonomous build mode (D1); a worker on a whole issue opens its own PR. Rejected: O18, remove it.
- D10 (Q9): O20. `st-worker` opens each worker workspace with the user's full template layout (Main: agent + lazygit; Dev Servers; VM), with the worker agent in the Main tab, so a dev server can run in that workspace. Rejected: O19, one agent tab only.
- D11 (Q10): O21. Each advisor point runs one time per gate. A REVISE with only MEDIUM and LOW findings counts as passed: the orchestrator handles the findings and does not run the point again. It runs again only when a CRITICAL or HIGH finding changed the plan, or the plan's approach changed. The limit stays at 2 runs per gate. Rejected: O22, run again after every REVISE.
- D12 (Q12, Q13, Q14): O24 as O27. When Claude Code runs in herdr, Codex runs as a herdr agent: one per workspace, in its own tab of the same workspace, started by Claude Code with `herdr agent start --kind codex`. Codex runs read-only and never asks (`-s read-only -a never`), so there is no permission prompt to approve. Claude Code sends each review with `herdr agent prompt` and reads the answer with `herdr agent read`; Codex gives its answer as JSON between two marker lines, checked against today's format (verdict, findings, levels); a bad answer counts as BLOCKED. Codex starts a new conversation per feature and keeps its memory inside one feature. The user can watch the tab and type to Codex. Outside herdr, Codex runs in the background as today. Rejected: O23 (saved session plus a `codex resume` line), O25 (`codex exec` per review in the tab), O26 as first worded (answer read from plain screen text).
- D13 (Q11): O28. At the Inspect gate, when the plan changed only by fixes of findings (Codex or Inspect) with no new approach, the orchestrator runs `st-advisor.sh waive plan <feature> "<reason>"`, which calls no Codex and writes a `WAIVED` line with the new fingerprint and the reason to `advisor.md`; `check plan` then passes. A changed approach (also from a CRITICAL or HIGH fix) runs Codex again, as D11's second run. The user sees the waive line and its reason at "OK to build?". Rejected: O29, Inspect never checks Codex again.
- D14 (Q15): O30. The `/advisor` review at the end of Build is skipped when every story had an `st-review` and no code changed after the last review; otherwise it runs one time, on the changes after the last review only. At the end of Build the orchestrator shows the count of advisor calls: Codex runs, waive lines and `/advisor` calls. Rejected: O31, always run on the full diff.
- D15 (Q16): O32 with an advisor matrix. The orchestrator makes a small decision at once, writes it in a list, and at each story review the list goes to the advisors the matrix names; any advisor can send a decision to the user, and it is undone if the user says no. The matrix: the orchestrator picks a risk level with the lane and shows it in the lane line (the user can change it). High: privacy and access, data model, contracts, secrets, money, cannot be undone. Normal: other Full work. Low: Fast. None: Quick and Design. Per point: plan review and Inspect re-check: High both, Normal Codex, Low none. Test red after 2 tries: High Codex then both if still red, Normal Codex, Low `/advisor`. Small decisions: High both, Normal Codex, Low `/advisor` at the end of the change. Fast diff: Low `/advisor`. End of Build (when D14 does not skip it): High both, Normal Codex. `.stratum/advisor.json` gets mode `auto` (the matrix, the new default); `codex`, `both` and `off` stay and override it. D11's run limits stay. Rejected: O33, each small decision goes to the advisors before the orchestrator acts; and one fixed advisor setting for every case.
- D16 (Q17): O35, as an experiment. In High cases the two advisors first review alone, then talk back and forth (Codex through its herdr tab, `/advisor` through the conversation) until they agree; the orchestrator makes one combined list (agreed, disputed with both reasons, found by one and not rejected). Disputed big ones go to the user with both views. Rejected for now: O34, two fixed rounds; it can replace O35 later.
- D17 (Q18): O36, changed. The talk has at most 3 back-and-forth rounds after the first review. It does not stop at an impasse: in the last round each advisor must propose a compromise for every open point, aimed at the best output. A compromise both accept is a combined finding. A point with no compromise both accept goes to the user, with both views in short, simple words. Each talk is recorded in `advisor.md`: rounds, agreed points, compromises, points sent to the user, and the number of calls, so O35 can be compared with O34 later. Rejected: O37, no limit and no record.
- D18 (Q19): O38. One test rule for every agent and lane: never the full suite unless the user asks in their own words. Default: list the changed files, grep the files that import them, run the tests of those files. Ask the user when that cannot work (shared config, test setup, a schema or migration, middleware, or a file more than 20 other files import): say why in short words and offer a named list of tests or the full suite. Planned tasks never have a "full suite" step; they name the exact test command. Rejected: O39, the orchestrator picks the full suite by itself for risky changes.
- D19 (Q20): O41, with a full check. When the git guard cannot read the whole command, it reads each line that has `git` alone and checks the full git command and its parameters with today's rules. Safe commands run. A `git` it cannot read as a full command asks. A command with no `git` runs. Tests: heredoc with `git status` runs, heredoc with `git commit` asks, Python code that calls git asks, heredoc with no git runs. Rejected: O40, ask whenever `git` is in an unreadable command.
- D20 (Q21): O42. Stratum gives one small lock script for tests that cannot run at the same time (the tests D3 marks): one run at a time per project, the others wait for the lock, a time limit (about 10 minutes) after which the agent stops waiting and reports to the orchestrator, which tells the user. It works on Linux, macOS and Windows (Git Bash): no `pgrep`, no `flock`. "Never write your own wait loop" goes into `st-test`, `st-build`, `st-debug` and the worker brief. The full suite stays ask-only (D18). The parasat constitution fix is out of scope; the user gets the line to change. Rejected: O43, no Stratum rule.
- D21 (Q22): O44. Autonomous build mode turns on only when the user says so in their own words in the request ("build with workers, autonomous", "autonomous mode"); the orchestrator shows "Autonomous build mode: on for this run". It lasts one run: it ends when the Build or worker run ends, and a new session never starts in it. "stop autonomous" turns it off at any time; new prompts then go to the user. The status line shows "autonomous" while it is on. Rejected: O45, a setting in `.stratum/` that stays on.
- D22 (Q23): O46. D1 to D21 are this feature's lane review. In the Plan phase the planner also lists every lane step the new rules make out of date or wrong and fixes it in this feature; anything bigger goes to the user as a question. Define, Close and Quick stay as they are. The user wants a fuller workflow review later (a new feature, with #56). Rejected: O47, review Define, Close and Quick step by step now.
- D23 (Q24): O48. In autonomous build mode a worker's commit is small and safe, and the orchestrator may approve it one time, only when all are true: it runs in the worker's own worktree, on the worker's own branch, it stages only files its task owns, and it has no `--amend` and no `--no-verify`. Anything else goes to the user. Rejected: O49, every worker commit goes to the user.
- D24 (orchestrator, F2): FR-012's default: an `advisor.json` with no `mode` key means `auto`; no `advisor.json` stays off, so nothing goes to Codex before the user sets it up.
- D25 (Q25, Inspect F5): O50. Codex in the herdr tab runs with a Stratum-owned `CODEX_HOME` that holds only a link to the user's Codex login, so the user's global `~/.codex/config.toml`, `~/.codex/hooks.json` and a trusted project's `.codex/config.toml` do not load; the model comes from `.stratum/advisor.json`, as with `--ignore-user-config` today (006 D23). The folder is made only when the user opts in to a Codex advisor (at `st-init` setup, or when the user asks to add a Codex advisor or sets a mode that uses Codex). The plan probes it live first; if it does not work, Codex runs in the background as today and the tab is not used. Rejected: O51, the tab Codex uses the user's global Codex settings.
- D26 (orchestrator, Inspect F15): FR-009 uses only POSIX shell tools (no `pgrep`, no `flock`) so it runs on Linux, macOS and Git Bash; it is tested on Linux only.
- D27 (Q26, Inspect F7): O52. Two locks against a worker approving itself: (1) the approval hook acts only when autonomous mode is on for the orchestrator's session (the main checkout's `.stratum/autonomous`, found through the git common dir, holds that session id); in normal mode or after "stop autonomous" it does nothing and every prompt stays for the user; (2) a PreToolUse check in worker sessions denies any Bash command, Edit or Write that touches `.stratum/approve/`. README states the remaining risk: a worker that works around both on purpose is not stopped. Rejected: O53, a README note only.
- D28 (Q27): O55. Autonomous build mode works for workers on any saved machine, since Stratum is built to work across machines. At `start --autonomous --machine <m>`, Stratum writes the orchestrator's session id into that machine's main checkout `.stratum/autonomous` over ssh, and removes it on "stop autonomous" and at the end of the run. A file left by a crashed session is replaced by the next `start --autonomous` on that machine; `autonomous-off` removes only a file that holds its own session id. A stale flag and session pair still match each other, so the hook sends the request and waits up to 300 s with the dialog showing, but no live orchestrator holds that id, so `approve` refuses and nothing is approved. Rejected: O54, autonomous mode only for workers on this machine.
- D29 (Q28): FR-019 has no user-granted-permission fallback. The hook is the only approval route. If the plugin hook in hooks/commands.json does not fire, start --autonomous loads the same hook with --settings (T034 contingency, user OKs it before it is built). If that also fails, autonomous mode stays off and every prompt goes to the user as in normal mode. No standing permissions. Rejected: O57 (permissions the user grants at worker start).
