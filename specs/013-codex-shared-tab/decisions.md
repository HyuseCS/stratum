# Decisions: #75 and #74 (shared Codex tab, answer summoned agents' prompts)

- D1 (O1/O2): O1. The Codex tab runs with the user's own CODEX_HOME and normal approvals. Each advisor review is checked after the turn (git status --porcelain plus a hash of untracked files, before and after); any change fails the point. The advisor prompt and the st-build skill say Codex makes no change and only advises, unless the user drives the tab for something else. Git is the undo. Rejected: O2 (keep the read-only session, user switches mode in it).
- D2 (Q1): O3. A change found by the after-turn check fails the point as BLOCKED. The orchestrator lists the changed files and asks the user; nothing is reverted. Rejected: O4 (script reverts the files itself).
- D3 (Q2): O5. Before it sends a prompt, the script checks the tab agent's state. On working or blocked it does not type into the tab; it runs the review headless at once and prints `codex: headless (Codex tab in use)`. Unsent text in the tab cannot be seen; mark that limit with a ponytail note. Rejected: O6 (wait up to about 4 minutes for idle).
- D4 (Q3): O7. One Codex tab per workspace and folder, named `st-codex`. The script never closes it. When the model or effort in advisor.json changes, the tab keeps the old values and the point prints a line telling the user to close the tab to apply them. A tab the user closed is opened again at the next point. Rejected: O8 (one tab per feature, ask before closing).
- D5 (Q4): O9. Remove the Stratum Codex home: the tab starts with the user's own CODEX_HOME; the `codex-home` command, its BLOCKED check and the `untrusted` entry go; st-init, st-build, README and tests change to match. The old folder on disk stays; tell the user they may delete it. Rejected: O10 (keep codex-home and link config, history and skills into it).
- D6 (Q5, Q6): O13. The orchestrator owns the Codex tab. The point runs in the background and the orchestrator starts a monitor on the tab as soon as it exists. On a prompt the script keeps waiting (no quit, no headless fallback); the orchestrator reads the screen and answers through a new `st-advisor.sh answer --keys ...` command, so the review goes on in the tab. It approves what Codex needs to advise: reading files anywhere, and read-only commands (tests, lint, git log, git diff). It never approves a file write or delete, a git change (commit, checkout, reset, push), an install, or .env and secrets; every other prompt goes to the user with the exact screen text, and the tab stays open. The D2 check still runs after the turn. Rejected: O11 (answer nothing, go headless), O12 (script presses No itself), O14 (approve every prompt).
- D7 (Q7): O15. In normal mode the orchestrator answers a worker's permission dialog with `answer --keys`, using autonomous mode's allow list and never list; every other dialog goes to the user with workspace, tab and exact text. The #74 rule goes into skills/st, skills/st-build and skills/st-worker; st-worker SKILL.md:26 changes to match. Rejected: O16 (normal mode keeps sending every dialog to the user).
- D8 (Q9): O19. Split #74. This feature is #75 plus #74 item 1 (D1 to D6). D7 (worker dialogs) and Q8 (#74 item 4, in-session subagent note; recommended O17, not yet answered) move to a second change after this one. #74 stays open until then. Rejected: O20 (all of #74 in this feature).
- D9 (Q10): O21. Done when the stub tests pass with a negative control for each new guard (after-turn change check, busy tab goes headless, no close on settings change, wait on a prompt, `answer` command, Codex home removed), and one live run in herdr passes: the user watches a review in the tab, types in the tab between two points, and one real prompt is answered by the orchestrator; that prompt's text is saved into the tests. Rejected: O22 (stub tests only).
- D10 (Q11, plan): the tab's agent name is `st-codex-<herdr workspace label>`, because herdr agent names are unique per server. The label is lowercased, every character outside `a-z0-9_-` becomes `-`, and it is cut so the name stays within 32 characters; a label with no letter or digit uses the workspace id instead. If the name is live in another workspace or folder, the point runs headless with a line that says so. The tab label stays `Codex`. Rejected: O23 (`st-codex-` plus a hash), O24 (one `st-codex` per server).
