# Decisions: #77 autonomous mode in more than one worktree (Define)

- D19 (Q19): One file per session: `<main checkout>/.stratum/autonomous/<session id>`. On makes this session's file, off removes only this session's file; readers check that `<folder>/<this session id>` exists. A session id must match letters, digits and `-` only. Lock 2 still matches `.stratum/autonomous`. An old single-file flag is replaced when a session turns the mode on. Same layout on a saved machine. Rejected: O1, one line per session id in the same file.
- D20 (Q20): No cleanup of other sessions' files. Instead the session turns its own mode off as soon as its task is finished (Build or worker run ends), when the user says "stop autonomous", and also when the user says they will continue some other time (before the handoff). Only a crashed session leaves a file, and that file affects only its own session id. Rejected: O42, remove files older than 24 hours.
- D21 (O54): The user added two fixes to #77: `answer` treats the "Ready to submit your answers?" screen as a question (FR-014), and the orchestrator approves a one-time yes on a cut-off permission dialog when the visible part is safe and the hidden part can only be the worker's own worktree or scratchpad (FR-015). The user's final rule (2026-11-08): never approve a cut-off dialog. Answer No and ask the worker for a rerun that shows the whole command or path (FR-015). Rejected: separate issues.
- D22 (O57, PR #91 review F1): `answer` only sent a one-time yes on a permission dialog, so the FR-015 No could not be sent. `answer` now also sends an option that starts with "No", with the same screen-hash match, and refuses one that says "don't ask again", "always", "this session" or "in the future" or names a host. The rerun request is a typed message: `answer --text` when the worker asks what to do differently, else tell the user (FR-016). Rejected: send the dialog to the user every time.
- D23 (change 001, GitHub #116, user 2026-11-20): `/stratum:st-autonomous on|off` replaces the plain words. Only the user's own `/stratum:st-autonomous on` turns autonomous build mode on, and the user turns it off with `/stratum:st-autonomous off`. The skill has `disable-model-invocation: true`, so the model cannot start it, and the orchestrator never runs `st-worker.sh autonomous-on` itself. Plain words ("autonomous mode", "build with workers, autonomous", "stop autonomous") turn nothing on or off: the orchestrator says in one line which command to run, and starts no worker for a plain-words turn-on request. The automatic ends stay: the end of the Build or worker run, and before the handoff (FR-010). Both `skills/st/SKILL.md` and the `on` step of the new skill teach them, so a session that never ran `/stratum:st` also ends the mode. This supersedes in this feature: US1 "The user says "autonomous mode"" (spec.md:16), US2 "the user says "stop autonomous"" (spec.md:42), the turn-on and "stop autonomous" parts of FR-009 (spec.md:104), the "stop autonomous" end of D20. In feature 010: FR-018 (spec.md:311), the "stop autonomous" end at spec.md:328, D9 (the orchestrator puts workers in autonomous mode), D21, D27 and D28. quickstart.md steps 1, 2 and 5 (lines 27, 28, 31) named the plain words; they now name the command. Rejected: the command beside the plain words.
